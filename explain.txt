# Project Technical Documentation & Presentation Guide

This document explains the core concepts used in this project using a 3-level breakdown:
1.  **🎓 CS Graduate:** Technical, precise, and academic.
2.  **🎒 High School Student:** Relatable, using basic physics and code concepts.
3.  **👶 5-Year-Old:** Simple analogies.

## 1. The Sensor: Accelerometer (MMA8451Q)

**What is it doing?**
*   **🎓 CS Graduate:** The MMA8451Q is a MEMS (Micro-Electro-Mechanical System) accelerometer that measures proper acceleration. When stationary, it measures the magnitude and direction of the gravity vector (1g) relative to the sensor's local frame of reference.
*   **🎒 High School Student:** It's a sensor that detects force. Even when it's not moving, it feels the Earth pulling it down (gravity). By checking which side is being pulled "down" the hardest (X, Y, or Z), we know how the board is tilted.
*   **👶 5-Year-Old:** Imagine a tiny heavy ball inside a box. If you tilt the box, the ball rolls to one side. This sensor feels where the ball is pushing to know if the box is tilted.

---

## 2. Signal Processing: Simple Moving Average (SMA) Filter

**Why do we need it?**
*   **🎓 CS Graduate:** The raw sensor data contains high-frequency noise (jitter). We implement a Finite Impulse Response (FIR) filter, specifically a Simple Moving Average, to act as a low-pass filter. This smooths the signal by averaging the last $N$ samples ($N=10$) in a circular buffer.
*   **🎒 High School Student:** The raw numbers from the sensor shake a lot, even when the board is still (like a shaky hand holding a camera). We take the last 10 numbers, add them up, and divide by 10 to get a smooth average. It makes the movement look fluid instead of twitchy.
*   **👶 5-Year-Old:** The sensor is a bit too excited and jumps around. We tell it, "Calm down, just tell me where you were mostly standing in the last second," and it gives us a steady answer.

---

## 3. The Math: Calculating Pitch & Roll (`atan2`)

**How do we get angles from forces?**
*   **🎓 CS Graduate:** We convert the Cartesian acceleration vector $(x, y, z)$ into Euler angles. **Pitch** (rotation around X) is calculated as $\arctan2(y, z)$, and **Roll** (rotation around Y) is $\arctan2(x, z)$. `atan2` is preferred over `atan` because it handles all four quadrants and avoids division-by-zero errors when $z=0$.
*   **🎒 High School Student:** We use trigonometry. If gravity is pulling mostly on the Z-axis, we are flat. If it starts pulling on the Y-axis, we are tilting. The `atan2` function takes these X/Y/Z forces and calculates the exact angle in degrees (or radians) that the board is tilting.
*   **👶 5-Year-Old:** We use a special math machine. We feed it the numbers "How much X push?" and "How much Z push?" and it spits out "You are tilted 45 degrees!"

## 4. Communication: UART & Floating Point

**The "Printf" Bug**
*   **🎓 CS Graduate:** Embedded Standard Libraries (Newlib-nano) often disable floating-point support in `printf` to save flash memory. Our initial code failed to print decimals (`%f`). We fixed this by overriding the `target.printf_lib` configuration in `mbed_app.json` to link the standard version.
*   **🎒 High School Student:** The board's brain is small, so it usually doesn't know how to print text with decimals (like 1.55). It tried to print just "%f" instead of the number. We had to change a setting to teach it how to speak "decimal" so it could send precise angles to the computer.
*   **👶 5-Year-Old:** The board tried to say "One and a half," but it didn't know the word "half," so it just stayed silent. We gave it a dictionary, and now it can say big, precise numbers.

## 5. Real-Time Data: WebSockets

**How does the website move instantly?**
*   **🎓 CS Graduate:** We use **WebSockets** (RFC 6455) instead of HTTP. HTTP is request-response (Client asks, Server answers). WebSockets provide a persistent, full-duplex communication channel over a single TCP connection, allowing the Python server to push filtered sensor data to the browser at 60Hz with minimal latency.
*   **🎒 High School Student:** Normal websites are like sending a letter and waiting for a reply. This project uses a "phone call" (WebSocket). The connection stays open, and the server screams new data to the website 60 times a second without waiting to be asked. That's why the 3D cube moves instantly.
*   **👶 5-Year-Old:** Instead of knocking on the door every time we have news, we installed a walkie-talkie. We just talk into it, and the website hears it instantly!

## 6. 3D Visualization: The Pivot Point

**Why did we rotate the cube in code?**
*   **🎓 CS Graduate:** The 3D model's local coordinate system didn't match the physical board's reference frame. We introduced a **Group** (Pivot) as a parent object. We apply the static coordinate transformation (rotation) to the *child* (the cube) and the dynamic sensor rotation to the *parent* (the pivot). This avoids Gimbal Lock and simplifies axis mapping.
*   **🎒 High School Student:** When we first made the cube, "up" on the screen wasn't "up" on the board. Instead of doing crazy math every frame to fix it, we put the cube inside an invisible box (the pivot). We rotate the cube once to lie flat inside the box, and then we just spin the invisible box using the sensor data.
*   **👶 5-Year-Old:** The digital block was standing up when the real board was lying down. We couldn't fix the board, so we just tricked the computer by permanently tilting the digital block 90 degrees so they match.
