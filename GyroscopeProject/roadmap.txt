# Roadmap for Gyroscope Project

## Project Status: COMPLETE

All primary objectives for the real-time 3D gyroscope visualization have been met. The project is fully functional.

## Final Architecture
*   **Firmware:** The C++ code on the NXP board is optimized to read accelerometer data, calculate pitch and roll, and send it over serial at ~33Hz. It uses a custom configuration (`mbed_app.json`) to enable floating-point printing.
*   **Backend:** A Python server (`server.py`) reads the serial data, performs an automatic calibration on startup to zero the orientation, and broadcasts the calibrated data to the web client using WebSockets (port `8889`). It also hosts the static web files (port `8888`).
*   **Frontend:** A sophisticated web page (`index.html` and `visualization.js`) uses a modern `importmap` to load `three.js`. It renders a semi-transparent "liquid glass" cube, receives real-time data via WebSockets, and correctly maps the board's physical orientation to the 3D model's rotation. The initial orientation and rotation axes are calibrated and mapped for an intuitive user experience.

## Completed Milestones

### Phase 1: Firmware Development & Debugging
- ✅ **Initial Setup & Compilation:** Successfully set up the Mbed environment and compiled the base project.
- ✅ **Data Filtering:** Implemented a Simple Moving Average (SMA) filter to stabilize sensor readings.
- ✅ **High-Frequency Updates:** Modified the firmware to send data every 30ms for a smooth 60fps experience.
- ✅ **Pitch & Roll Calculation:** Added `atan2` logic to convert raw accelerometer data into pitch and roll angles.
- ✅ **Firmware Bug Fix (`printf`):** Diagnosed and fixed a critical bug where floating-point numbers were not being printed. Solved by creating `mbed_app.json` to force the use of the standard `printf` library.

### Phase 2: Web Backend & Frontend Integration
- ✅ **Python Server Creation:** Built a Python backend using `http.server` and the `websockets` library.
- ✅ **Initial 3D Scene:** Created the initial `index.html` and `three.js` script.
- ✅ **Cyberpunk Styling:** Implemented a "cyberpunk" theme with a dark background, grid, and glowing elements using `UnrealBloomPass`.
- ✅ **User-Led Frontend Overhaul:** Successfully integrated the user's superior frontend code, which included a modern `importmap`, a more robust UI, and cleaner JavaScript (`visualization.js`).

### Phase 3: Debugging & Final Calibration (The "Nail It" Phase)
- ✅ **Browser Caching Issues:** Diagnosed and solved multiple layers of browser caching problems, culminating in the user's implementation of an `importmap`.
- ✅ **WebSocket Connection Issues:** Debugged and resolved multiple WebSocket errors (`InvalidUpgrade`, `CONNECTION_RESET`) by finding a compatible library version (`websockets==10.4`).
- ✅ **Rotation Axis Mapping:** Corrected the mapping in `visualization.js` so that the physical roll and pitch of the board intuitively match the on-screen 3D model's rotation.
- ✅ **Visual Style Update:** Changed the model to a semi-transparent "liquid glass" cube as requested.
- ✅ **Initial Orientation Fix:** Implemented a pivot system in `three.js` to ensure the 3D model starts in the correct "lying flat" orientation.
- ✅ **Automatic Calibration:** Implemented a calibration sequence in `server.py` that automatically "zeroes" the sensor data based on the board's orientation at startup.

### Future Phases (Ideas)
*   **Step Counter:** Build upon this project by adding an algorithm to detect and count steps from the accelerometer data.
*   **Velocity/Position Tracking:** Experiment with integrating acceleration data, keeping in mind the limitations due to sensor drift.
*   **UI Controls:** Add on-screen controls to reset the calibration or change visual styles.
